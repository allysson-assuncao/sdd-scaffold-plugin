# Skill: `sdd-init` — SDD Project Scaffolding

This skill bootstraps the Spec-Driven Development infrastructure in any software project through an interactive, agent-driven setup conversation.

---

## When to Activate

Activate this skill when the user:
- Starts a brand new software project and wants to use SDD from day one.
- Has an existing project and wants to adopt the SDD methodology.
- Explicitly says "sdd init", "initialize SDD", or "scaffold my agents directory".

---

## Procedure

### Step 1: Gather Project Context

Ask the user the following questions (can be asked together in one message):

1. **Project name** — What is the name of this project? (Used for directory naming and artifact IDs.)
2. **Primary language/stack** — What is the main technology stack? (e.g., Python/FastAPI, Java/Spring Boot, TypeScript/Next.js, Go, Rust). This is for metadata only; no stack-specific code will be generated by this plugin.
3. **Governance mode** — Is this for:
   - **Personal** (just you, global plugin reference), or
   - **Team** (multiple developers, plugin referenced via Git-checkable `.agents/plugins.json`)?
4. **Specs directory preference** — Where should specification files live?
   - `specs/` (recommended — top-level, visible, version-controlled)
   - `docs/specs/`
   - `.agents/specs/`

### Step 2: Read Templates

Read all template files from `skills/sdd-init/resources/templates/`. These contain `{{PLACEHOLDER}}` markers for substitution.

### Step 3: Substitute Placeholders

Replace the following placeholders in all templates:

| Placeholder | Value |
|---|---|
| `{{PROJECT_NAME}}` | Project name from Step 1 |
| `{{STACK}}` | Stack from Step 1 |
| `{{DATE}}` | Today's date in YYYY-MM-DD format |
| `{{SPECS_DIR}}` | Specs directory preference from Step 1 |
| `{{GOVERNANCE_MODE}}` | `personal` or `team` |

### Step 4: Write the Scaffold

Create the following structure in the project root:

```text
.agents/
├── AGENTS.md          # From AGENTS.md.tmpl — project constitution
└── plugins.json       # From plugins.json.tmpl — inherits global SDD plugin

{{SPECS_DIR}}/
└── .gitkeep           # Empty placeholder — first spec goes here
```

If governance mode is **team**, also write a comment in `plugins.json` explaining Git-based distribution.

### Step 5: Confirm and Summarize

Present the created file tree to the user:

> _"SDD scaffold created! Here's what was generated:_
> _- `.agents/AGENTS.md` — your project's agent constitution_
> _- `.agents/plugins.json` — inherits `sdd-scaffold-plugin` globally_
> _- `{{SPECS_DIR}}/` — ready for your first `spec.md`_
>
> _To begin your first feature, activate the `spec-architect` skill."_

---

## Script Helpers

For users who prefer CLI automation over the conversational flow, helper scripts are available:

- **Windows:** `skills/sdd-init/scripts/scaffold.ps1`
- **Unix/macOS:** `skills/sdd-init/scripts/scaffold.sh`

These scripts accept `--project-name`, `--stack`, and `--specs-dir` flags and perform Steps 2–4 non-interactively. The agent still performs Step 5 (confirmation) after the script completes.

---

## Notes

- **Idempotent:** If `.agents/` already exists, the skill will diff the existing files against the templates and only propose changes for files that are missing or outdated.
- **Non-destructive:** Existing `.agents/rules/` overrides are never touched.
- **Stack-agnostic:** This skill does not generate stack-specific boilerplate. For stack setup, activate the appropriate `<stack>-stack` skill after SDD init.
